# Languages and translation contributions

DESLOC bundles 24 complete Home Assistant language packs:

- English (`en`), العربية (`ar`), বাংলা (`bn`), Čeština (`cs`)
- Deutsch (`de`), Español (`es`), فارسی (`fa`), Français (`fr`)
- עברית (`he`), हिन्दी (`hi`), Bahasa Indonesia (`id`), Italiano (`it`)
- 日本語 (`ja`), 한국어 (`ko`), Nederlands (`nl`), Polski (`pl`)
- Português (`pt`), Русский (`ru`), ไทย (`th`), Türkçe (`tr`)
- Українська (`uk`), Tiếng Việt (`vi`), 简体中文 (`zh-Hans`), 繁體中文 (`zh-Hant`)

## Translated surface

Setup, session import, email verification, reauthentication, setup errors and
completion messages, the permanent PIN user form, and its safety messages are
translated. Battery, Wi-Fi signal, and raw diagnostic sensor names have native
entity translation keys. Lock-command errors also carry native Home Assistant
translation metadata, including uncertain results and expired sessions.

Home Assistant selects its own UI translations from the user's language.
Generated entity names use Home Assistant's system language. A name you set
manually takes priority. Existing entity IDs, unique IDs, automations, and device
names from your DESLOC account are preserved when the language changes or the
integration is reloaded. Lock states use Home Assistant's built-in translations.
Arabic, Hebrew, and Persian use the standard Home Assistant right-to-left UI;
this integration does not introduce a custom direction or language switcher.

Raw protocol values, diagnostic attribute keys such as `model_validation`, API
errors in logs, user-entered names, credentials, PINs, and entity identifiers are
not translated. Documentation, screenshots, and the video remain in English.
The separately installed [DESLOC Lock Card](https://github.com/ha-homelab/ha-desloc-card)
has its own bundled translations and release cycle.

## Runtime and safety

All language files ship inside the integration. No translation service receives
account details, names, PINs, or other text. Home Assistant's native translation
loader provides English fallback for an unavailable language. We do not use
fallback to advertise partial language packs.

Translation changes do not send commands or change authentication behavior.
A revoked session still requires reauthentication without an automatic login.
An uncertain command or PIN result still requires checking the lock or DESLOC
app before retrying. Existing users never receive another PIN through this
form, and an entered PIN is not compared with an existing PIN. All these
messages are translated as complete sentences, not assembled fragments.

## Contributing

1. Edit `custom_components/desloc/translations/en.json` as the canonical English
   vocabulary. Keep `strings.json` identical as an authoring and validation
   mirror; runtime custom-component translations come from `translations/`.
2. Update every language pack with the same keys. Use complete localized text,
   not Home Assistant Core's build-time `[%key:...%]` references. Preserve any
   named `{placeholders}`, numerical limits, product names, and security meaning.
3. To add a language, use a supported Home Assistant language filename, update
   the list above and `LOCALES` in `tests/test_translations.py`, and translate
   every canonical message. Chinese uses the native `zh-Hans` and `zh-Hant`
   filenames; Portuguese uses `pt`.
4. Run the checks below and inspect the actual Home Assistant dialogs in that
   language. For a naming change, also verify that existing custom names and
   entity IDs remain unchanged.

```sh
python3 -m pytest tests/test_translations.py tests/test_commands.py tests/test_pin_users.py -q
python3 -m pytest -q
```

The existing CI pytest job runs these translation tests. They check complete
key coverage, duplicate JSON keys, placeholder parity, accidental English copies,
unresolved Core references, and the actual Home Assistant loader for every
language. A synthetic setup/reload test verifies translated sensor names and
preservation of entity IDs, unique IDs, and custom names. No test communicates
with a physical lock or the DESLOC cloud.

Automated checks cannot certify idiomatic wording in all languages. Native
speaker corrections are welcome. Include the language, screen, current wording,
and suggested wording, using fictional names and never including credentials,
PINs, or session tokens. Preserve the distinction between an unsuccessful read,
a command that was never sent, and an uncertain result after a write.
