    01 / GET STARTED

    A small setup.
    A familiar home.

    Both projects are in the default HACS catalog. Install the integration first, then add the optional card.

    Before you begin

    Use Home Assistant 2026.9.1 or newer, with your lock already paired to the DESLOC app and working cloud control. HA needs HTTPS access to appadmin.desloc.com. HACS is optional; manual installation is below.

    THE CONNECTION

    DESLOC integration

    1. Open HACS and search for DESLOC.
    2. Download the latest stable release.
    3. Restart Home Assistant.
    4. Go to Settings → Devices & services → Add integration → DESLOC.
    5. Connect your account. Every returned lock is added automatically.
    Latest integration release ↗
    THE INTERFACE

    DESLOC Lock Card

    1. Open HACS and search for DESLOC Lock Card.
    2. Download the latest stable release.
    3. Reload your browser.
    4. Edit a dashboard and add DESLOC Lock Card or DESLOC Compact Lock Card.
    5. Select your lock and optional battery and Wi-Fi sensors in the editor.
    Latest card release ↗

    Keep prerelease versions disabled for everyday use. Beta, RC, nightly and main builds are opt-in testing channels.

    Install manually without HACS

    Integration

    Download ha-desloc.zip and SHA256SUMS from the stable release, verify the checksum and extract the ZIP. Copy its custom_components/desloc directory into your HA configuration directory. The final path must be /config/custom_components/desloc/manifest.json. Restart HA and add DESLOC from Devices & services.

    Card

    Download ha-desloc-card.js from the card release to /config/www/ha-desloc-card.js. Register /local/ha-desloc-card.js as a JavaScript module in Settings → Dashboards → ⋮ → Resources. Enable Advanced mode in your HA profile if Resources is hidden. Restart HA if you just created www, then reload the browser.

    For Container installations, use the host directory mounted at /config. Do not register both HACS and manual card resources at the same time.

    Update an existing installation

    Download the newer stable integration through HACS and restart HA. Download the newer card and reload the browser. Existing integration entries and entity IDs are retained; adding DESLOC again is unnecessary.

    For manual updates, back up your configuration, replace only the integration directory or card JS file, then restart HA or reload the browser respectively. Updating this website does not update your HA installation.

    02 / YOUR ACCOUNT

    One account.
    Every returned lock.

    Setup creates a separate entry and set of entities for every lock returned by DESLOC. Choose the authentication method that fits your household.

    Email & password

    Choose Sign in with email and password, enter your DESLOC credentials and complete email-code verification if requested.

    A new login can invalidate another session on the same account, including the phone app.

    Existing app session

    Choose Use a captured app session to reuse the phone app’s validated session without another login. This is an advanced setup flow.

    Follow the session import guide. No proxy or capture tool is needed for normal operation afterward.

    Sessions are shared state

    Signing out of the app or signing in elsewhere can revoke the session used by HA. Use Reauthenticate, or the entry menu’s Reconfigure action, to replace it. HA never repeatedly logs in in the background after a rejected session.

    Already paired another lock?

    Run Reconfigure on an existing DESLOC entry. Setup and reconfiguration add newly returned locks; regular polling does not create new entries. Existing entity IDs are preserved and disabled entries remain disabled.

    Discovery currently reads the app’s default group. Multiple populated pages and multiple-home accounts still need broader community testing. A K120 owner reported success with a shared lock on a second account for HA; this is a community report, not a guarantee for every account.

    HA stores the session token and installation ID. New entries do not retain your password or email code. Treat HA configuration and backups as credentials.

    03 / MAKE IT YOURS

    Room to breathe.
    Or room for more.

    Full and compact layouts share the same resource, visual editor and command handling. There is no second download or account login.

    COMPACT LAYOUT

    Front door

    Locked · Battery 84% · −48 dBm

    Unlock ↗

    Illustrative layout with example readings, not a live device or a screenshot.

    Enable Compact layout in the visual editor, add compact: true to an existing card, or choose DESLOC Compact Lock Card in the card picker. Compact mode is available in card version 0.4.0 and newer.

    Dashboard YAML · use your own entity IDs
    type: custom:desloc-lock-card
entity: lock.front_door
name: Front door
battery_entity: sensor.front_door_battery
signal_entity: sensor.front_door_wi_fi_signal
compact: true

    Only entity is required. Omit sensors you do not have. For a new compact card, type: custom:desloc-compact-lock-card also works. Both layouts offer one action based on reported state:

    LOCKED

    Unlock

    Requires an explicit confirmation naming the selected lock.

    UNLOCKED

    Lock

    Sends the requested action once.

    PENDING

    Waiting

    The action is disabled. The ring means waiting, not success.

    UNCERTAIN

    Check first

    Unknown state never offers Unlock. An unavailable entity disables control.

    Your dashboard, your language

    The card follows your HA profile and includes 24 language packs. Select a per-card language in the editor or add language: fr to YAML. Arabic, Hebrew and Persian use right-to-left layouts. Unsupported languages fall back to English; no translation service is contacted.

    The card does not appear after installation

    Reload the browser after updating. If HACS did not register its resource, add /hacsfiles/ha-desloc-card/ha-desloc-card.js as a JavaScript module under Dashboard Resources. Do not register it twice. Make sure you installed the card as well as the integration.

    Why can a stable release say “experimental”?

    Release stability and model validation are separate. D110 Plus, K120 and other models retain an experimental runtime label until maintainer validation is available. Community evidence is recorded here without overstating its scope.

    Other DESLOC-app models are welcome for testing. Locks paired only to TTLock or Tuya accounts are outside this integration’s scope. Read the full compatibility record or report your model.

    05 / UNDER THE SURFACE

    One command.
    A careful confirmation.

    The card talks to Home Assistant. The integration talks to the DESLOC cloud. Your lock connects over Wi-Fi.

    1

    Send once

    After you confirm Unlock, the integration sends one command. It does not retry a physical action automatically.

    2

    Wait visibly

    The card disables its button and shows a loading ring while the operation is pending.

    3

    Require fresh state

    Confirmation requires a strictly newer report matching the requested state. A cloud acknowledgement or an old matching reading is not enough.

    4

    Keep uncertainty honest

    If confirmation does not arrive within the command window, the action is reported as unconfirmed. The lock may still respond later. Check it physically before trying again.

    60 s

    Normal polling interval

    Coordinators using the same account session share device-list reads. Reported values may be cached by the cloud.

    45 s

    Command confirmation window

    If the cloud result expires, read-only state checks continue every 2 seconds within the original window. No new command is sent.

    These timings describe the documented implementation, not a response-time guarantee. There is no local, offline or Bluetooth control, activity history, jam detection, or door-open sensor. Reported bolt state cannot tell you whether the door is physically open.

    06 / SHARE ACCESS

    A PIN for someone
    you trust.

    Create a regular user with permanent access to one selected lock. This is an administrator workflow in the integration, separate from the dashboard card.

    1. Open Settings → Devices & services → DESLOC.
    2. Choose Configure on the entry for the intended lock.
    3. In Add a permanent PIN user, enter a unique user name of 1–24 characters.
    4. Enter a new 6–8 digit PIN, repeat it, and submit.
    5. Wait for the result, then separately verify the PIN at the physical keypad.
    Know the boundary

    The integration creates permanent PIN users; it does not edit or delete them, replace existing users’ PINs, or manage schedules. User creation and PIN installation are separate writes. A partial failure may leave a user without a working PIN. Inspect the DESLOC app before retrying.

    Configure opens PIN management. Reconfigure changes authentication. The PIN is not retained in HA configuration or state. Creating a PIN and lock/unlock cannot overlap for the same entry.

    07 / WHEN SOMETHING FEELS OFF

    Start with the symptom.

    A clear state is useful. An honest “unknown” is more useful than a false confirmation.

    Unknown state, but battery and Wi-Fi are visible

    Those readings can be cached independently. After an uncertain command, old bolt telemetry is suppressed until a newer state report arrives. A visible battery value does not prove that the lock is reachable now.

    Check the physical lock. Record what actually happened and download diagnostics before restarting or reloading the integration.

    “Command failed” — then the lock moved later

    A timeout means confirmation did not arrive within the observation window. It does not prove the physical action failed. DESLOC can deliver a command after that deadline.

    Do not repeatedly press the action. Check the physical lock first. The integration never retries a physical command automatically.

    The phone app asks me to log in again

    A fresh login on the same account can invalidate the other session. HA reuses its saved token and stops when it is rejected. Use interactive reauthentication or import the current app session.

    Signing out of the app may revoke an imported session too. See Connect your account; removing or pairing the lock again is unnecessary.

    A lock paired later is missing from HA

    Use the DESLOC entry menu’s Reconfigure action. Regular polling updates existing entities; setup and reconfiguration discover newly returned locks. Multiple-home accounts may require further compatibility investigation.

    The compact card or loading ring is missing

    Check that DESLOC Lock Card is updated to stable 0.4.0 or newer, then reload your browser. The integration and card are separate downloads. Check for a duplicate or stale resource in Dashboard Resources.

    The compact layout uses the same resource as the full layout. Reduced-motion preferences intentionally make the waiting ring static.

    A new release or its icon has not appeared in HACS

    GitHub publication and HACS refresh are separate events. Check the integration release and card release, then check the repository in HACS. Leave prereleases disabled for normal use.

    Branding also has its own upstream delivery and cache path. See the branding guide before reinstalling a working integration.

    A useful bug report starts before a restart

    Open Settings → Devices & services → DESLOC → entry menu → Download diagnostics. The latest command snapshot is held in memory, so collect it before reloading. Include your HA, integration and card versions, model, timestamps, physical outcome, and any manual, app or keypad activity.

    Use debug logging only during a deliberate reproduction, then turn it off. Review any file before sharing. Never publish session tokens, passwords, PINs, raw traffic captures or HA backups.

    feel at home.

    Report a model

    Include model, firmware/app versions, HA version, and exactly what works: discovery, state, battery, Wi-Fi, lock/unlock and PIN creation. Separate reported state from physical observations.

    Improve the interface

    For a card issue, include browser and HA versions, full or compact layout, and an anonymized card configuration. For translations, preserve placeholders and the intended action.
